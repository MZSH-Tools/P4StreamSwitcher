# 极速切换

## 需求

- [x] 已存在的工作区直接打开 P4V，不执行任何同步操作
- [x] 只有创建新工作区时才执行同步流程
- [x] 最大化切换速度

## 设计方案

### 核心思路

区分"切换到已有工作区"和"创建新工作区"两种场景：

- **已有工作区**：用户之前已切换过，本地文件已同步，无需再次同步
- **新工作区**：首次切换，需要执行完整同步流程

### 切换流程

```
选择项目/分支 → 生成工作区名称
            → 检查工作区是否存在？
            → [存在] → 更新时间戳 → 直接打开 P4V（极速）
            → [不存在] → 检查上限 → 创建工作区 → 执行同步 → 打开 P4V
```

### 同步流程（仅新工作区）

根据是否勾选"离线目录"：

**普通目录**：
1. sync -k 更新 have list
2. 删除多余文件
3. diff -se/-sd 检测差异
4. sync -f --parallel 下载

**离线目录**：
1. sync -k 更新 have list
2. reconcile 识别差异
3. 差异放入 changelist

### 性能对比

| 场景 | 耗时 |
|------|------|
| 已有工作区 | <1 秒（仅启动 P4V） |
| 新工作区（小项目） | 数秒 |
| 新工作区（大项目） | 数分钟 |

## 任务清单

- [x] P4Core.py - ClientExists（检查工作区是否存在）
- [x] Callbacks.py - OnApply 区分已有/新建逻辑
- [x] Callbacks.py - 已有工作区跳过同步
- [x] Callbacks.py - 更新时间戳

## 边界问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| 已有工作区但本地文件被删除 | 用户需手动处理或删除工作区重建 |
| P4V 启动失败 | 捕获异常，提示用户 |

## 用户体验

- 工作区名称预览：黑色表示已存在（极速），灰色表示待创建
- 状态栏显示当前操作状态
- 日志输出详细步骤
