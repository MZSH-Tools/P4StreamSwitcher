# 智能同步

## 需求

- [x] 解决 `clean` 命令删除缓存文件（Saved/、Intermediate/、DerivedDataCache/）导致重新编译的问题
- [x] 解决 `clean` 扫描 10 万+ 文件耗时过长的问题
- [x] 基于 `.p4ignore` 自动保护缓存文件

## 设计方案

### 文件分类逻辑

```
对于本地每个文件：
├── 在 have list 中？ → 保留（depot 管理）
├── 匹配 .p4ignore？ → 保留（缓存/忽略文件）
└── 否则 → 删除（多余文件）
```

### 同步流程

1. `p4 opened` 检查未提交修改 → 有则拒绝切换
2. 切换 Stream 和 Root
3. `sync -k` 更新 have list（不下载文件）
4. 读取并解析 `.p4ignore` 规则
5. `p4 have` 获取 have list（depot 文件 → 本地路径）
6. 遍历工作区 → 删除（不在 have list 且不匹配 .p4ignore）的文件
7. `diff -se` 检测内容不同的文件 → `sync -f --parallel` 覆盖
8. `diff -sd` 检测缺失的文件 → `sync -f --parallel` 下载

### 默认保护规则

即使没有 `.p4ignore` 文件，也自动保护以下目录：

| 目录/文件 | 说明 |
|-----------|------|
| Saved/ | UE 项目保存数据 |
| Intermediate/ | UE 中间文件 |
| DerivedDataCache/ | UE 派生数据缓存 |
| Binaries/ | 编译输出 |
| .vs/ | Visual Studio 配置 |
| .vscode/ | VS Code 配置 |
| .idea/ | JetBrains IDE 配置 |
| .git/ | Git 仓库 |
| .p4config | Perforce 配置文件 |
| *.log | 日志文件 |

## 边界问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| .p4ignore 不存在 | 使用默认保护规则 |
| 文件只读无法删除 | 删除前移除只读属性 |
| 同步失败 | 独立异常处理，继续后续步骤 |

## 废弃方案

| 方案 | 废弃原因 |
|------|----------|
| clean 命令 | 删除缓存文件，扫描慢 |
| 全量 sync | 网络开销大，耗时长 |
