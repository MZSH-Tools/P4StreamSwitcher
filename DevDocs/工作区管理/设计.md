# 工作区管理

## 需求

- [x] 通过工作区标识自动创建和管理多个工作区
- [x] 自动检测标识是否被其他主机使用
- [x] 标识冲突时支持批量重命名旧工作区
- [x] 工作区池管理，达到上限时自动删除最旧工作区
- [x] 删除前检查未提交修改
- [x] 基于时间戳判断最旧工作区

## 设计方案

### 工作区命名规则

```
{标识}_{项目}_{分支}
```

示例：`zhangsan_UE5_main`、`zhangsan_UE5_dev`

### 标识验证流程

```
输入标识 → 检查是否与已保存标识相同？
         → [相同] → 显示 O（有效）
         → [不同] → 检查是否被其他主机使用？
                  → [是] → 显示 X（冲突），禁用保存
                  → [否] → 显示 O（有效），启用保存
```

### 标识冲突检测

检查所有符合 `标识_*_*` 格式的工作区，如果存在非本机工作区则判定为冲突。

### 重命名流程

```
保存新标识 → 查找旧标识的本地工作区
          → 批量重命名为新标识格式
          → 迁移时间戳到新名称
```

### 工作区池管理

```
创建新工作区 → 检查已使用数量
            → [未达上限] → 直接创建
            → [已达上限] → 查找最旧工作区
                        → 检查未提交修改
                        → [有修改] → 拒绝并提示
                        → [无修改] → 删除后创建
```

### 时间戳管理

- 工作区每次使用时更新时间戳（LRU 策略）
- 时间戳存储在全局配置中
- 重命名工作区时迁移时间戳

```json
{
  "workspace_timestamps": {
    "zhangsan_UE5_main": 1705123456,
    "zhangsan_UE5_dev": 1705123400
  }
}
```

## 边界问题与解决方案

| 问题 | 解决方案 |
|------|----------|
| 标识为空 | 显示空状态，禁用保存 |
| 标识被其他主机使用 | 显示 X，弹窗提示冲突列表 |
| 最旧工作区有未提交 | 拒绝删除，提示用户处理 |
| 重命名失败 | 捕获异常，继续处理其他工作区 |
| 时间戳不存在 | 视为最旧（时间戳 = 0） |

## 废弃方案

| 方案 | 废弃原因 |
|------|----------|
| 手动管理工作区 | 操作繁琐，容易出错 |
| 按创建时间排序 | 服务器时间可能不准确 |
