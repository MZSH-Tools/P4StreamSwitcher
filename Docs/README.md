# P4StreamSwitcher 使用教程

## 功能介绍

P4StreamSwitcher 是一个基于 tkinter 的 GUI 工具，用于简化 Perforce 流工作区的切换操作。

### 主要功能

| 功能 | 说明 |
|------|------|
| 工作区标识 | 设置个人标识，用于自动生成工作区名称 |
| 最大工作区 | 限制工作区池大小，管理可用工作区数量 |
| 项目选择 | 显示所有 mainline 类型的流项目 |
| 分支选择 | 显示选中项目下的所有流分支 |
| 工作区名称 | 实时预览，黑色=已存在，灰色=待创建 |
| 工作区目录 | 可自定义切换后的本地工作目录 |
| 目录缓存 | 自动记住每个流对应的工作区目录 |
| 未提交检查 | 切换前检查是否有未提交修改 |
| P4V 检测 | 切换前检查 P4V 是否运行中 |
| 智能同步 | 基于 `.p4ignore` 保护缓存文件 |
| 状态栏 | 显示服务器/用户和使用工作区数量 |

## 环境配置

### 前置条件

1. 安装 Python 3.x
2. 安装依赖：
   ```bash
   pip install p4python platformdirs
   ```
3. 确保已配置 Perforce 环境变量：
   ```bash
   p4 set P4PORT=your.server:1666
   p4 set P4USER=your_username
   ```

### 验证环境

```bash
p4 info
```

如能正常显示服务器信息，说明环境配置正确。

## 使用说明

### 启动工具

```bash
python Main.py
```

### 界面说明

启动后界面分为以下区域：

**通用配置**
- **工作区标识**：输入个人标识（如姓名拼音），用于生成工作区名称
  - 标识后有验证状态：`O` 表示有效，`X` 表示冲突或为空
  - 点击保存按钮保存标识，如有旧标识工作区会提示重命名
- **最大工作区**：设置工作区池大小，控制可创建的工作区数量
- **创建 P4CONFIG**：创建工作区时在根目录生成 .p4config 文件（默认启用）
- **自动删除空文件夹**：设置客户端 rmdir 选项，sync 时自动清理空目录（默认启用）

**工作区配置**
- **选择流项目**：目标项目
- **选择流分支**：目标分支
- **工作区名称**：自动生成的工作区名称预览（`标识_项目_分支`）
- **工作区目录**：点击打开目录选择对话框
- **离线目录**：勾选后创建时以本地文件为准，使用 reconcile 识别差异
- **切换并打开 P4V**：执行切换操作并自动打开 P4V

**日志输出**
- 实时显示操作详情和进度

**状态栏**
- 左侧：当前状态（就绪/正在同步...）
- 中间：服务器地址和用户名
- 右侧：使用工作区数量（已用/最大）

### 操作步骤

1. **设置工作区标识**：首次使用需设置个人标识（自动保存）
2. **选择目标项目**：点击下拉框，选择目标流项目
3. **选择目标分支**：点击下拉框，选择目标流分支
4. **确认工作区目录**：点击可打开目录选择对话框修改路径
5. **点击"切换并打开 P4V"**：开始执行切换操作，完成后自动打开 P4V

### 切换流程

点击"切换并打开 P4V"后，工具会自动执行以下步骤：

1. **检查工作区标识**：如未设置或未保存，提示用户设置
2. **检查目标工作区**：
   - **已存在**：直接打开 P4V（极速，不执行任何同步）
   - **不存在且未达上限**：确认默认路径后，创建新工作区并执行同步流程
   - **不存在且已达上限**：检测最旧工作区是否有未提交文件或 P4V 正在运行
     - 有问题：报错并要求手动处理
     - 无问题：删除最旧工作区后创建新工作区

### 已存在工作区

直接打开 P4V，不执行任何同步操作，速度最快。

### 创建新工作区（非离线目录）

1. **检查目录**：如目录不存在，询问是否创建
2. **创建工作区**：创建客户端并设置 Stream 和 Root
3. **更新时间戳**：记录工作区使用时间（用于判断最旧工作区）
4. **更新 have list**：执行 `sync -k` 更新文件索引
5. **解析 .p4ignore**：读取忽略规则，保护缓存文件
6. **清理多余文件**：删除不在 have list 且不匹配 .p4ignore 的文件
7. **检测差异文件**：使用 `diff -se` 检测内容不同的文件
8. **检测缺失文件**：使用 `diff -sd` 检测本地缺失的文件
9. **同步文件**：使用 `sync -f --parallel` 下载差异和缺失文件
10. **打开 P4V**：自动启动 P4V 并切换到当前客户端

### 创建新工作区（离线目录）

1. **检查目录**：如目录不存在，询问是否创建
2. **创建工作区**：创建客户端并设置 Stream 和 Root
3. **更新时间戳**：记录工作区使用时间（用于判断最旧工作区）
4. **更新 have list**：执行 `sync -k` 更新文件索引
5. **执行 reconcile**：以本地文件为准，识别本地新增/修改/删除的文件
6. **放入 changelist**：所有差异放入默认 changelist
7. **打开 P4V**：自动启动 P4V，用户可在 P4V 中查看和处理变更

### 进度与日志

- 操作开始后会显示进度条
- 日志区域实时显示操作详情
- 操作完成后进度条自动隐藏

## 配置缓存

工具会自动保存以下配置：

- **工作区标识**：全局保存，下次启动自动加载
- **最大工作区数**：全局保存
- **工作区目录**：按流路径分别缓存
- **离线目录标记**：按流路径分别缓存

缓存存储在系统缓存目录中（Windows: `%LOCALAPPDATA%`，Mac: `~/Library/Caches`）

## 工作区管理规则

本工具只管理符合 `标识_项目_分支` 命名格式的工作区，用户自建的其他工作区不纳入管理。

- **使用工作区**：显示当前标识下已创建的工作区数量
- **命名格式**：`{工作区标识}_{项目名}_{分支名}`（如 `zhangsan_UE5_main`）
- **自动创建**：切换时如工作区不存在会自动创建
- **独立管理**：不同标识的工作区相互独立，不会互相影响

## 智能同步说明

### 缓存保护

工具会自动保护以下目录（即使没有 `.p4ignore` 文件）：

- `Saved/` - UE 项目保存数据
- `Intermediate/` - UE 中间文件
- `DerivedDataCache/` - UE 派生数据缓存
- `Binaries/` - 编译输出
- `.vs/` - Visual Studio 配置
- `.vscode/` - VS Code 配置
- `.idea/` - JetBrains IDE 配置
- `.git/` - Git 仓库
- `*.log` - 日志文件

### 自定义忽略规则

在工作区根目录创建 `.p4ignore` 文件，添加自定义规则：

```
# 忽略目录（以 / 结尾）
MyCache/
Build/

# 忽略特定扩展名
*.tmp
*.bak

# 忽略特定路径
Config/Local/*

# 取消忽略（! 前缀）
!重要文件.txt
```

## 常见问题

### 连接服务器失败

**错误提示**：请检查 p4 set 中 P4PORT

**解决方法**：
```bash
p4 set P4PORT=正确的服务器地址:端口
```

### 用户设置错误

**错误提示**：请检查 p4 set 中 P4USER

**解决方法**：
```bash
p4 set P4USER=正确的用户名
```

### 未检测到流客户端

**错误提示**：未在本地检测到用户 xxx 所属的流客户端

**原因**：当前主机没有属于该用户的流类型客户端

**解决方法**：
1. 使用 P4V 或命令行创建流客户端
2. 确保客户端的 Host 设置为当前主机名
3. 确保客户端关联了 Stream

### 缺少工作区标识

**错误提示**：请先设置工作区标识

**原因**：未设置个人标识

**解决方法**：
在通用配置区域的"工作区标识"输入框中输入个人标识（如姓名拼音），然后点击保存

### 工作区标识冲突

**错误提示**：该标识已被其他主机使用

**原因**：输入的标识已被其他主机的工作区使用（符合 `标识_项目_分支` 格式）

**解决方法**：
1. 更换一个唯一的标识
2. 或联系使用相同标识的用户协调

### 无法删除工作区

**错误提示**：无法删除工作区 xxx

**原因**：需要删除最旧工作区腾出空间，但检测到以下问题之一或全部：
- 待删除工作区有未提交文件
- P4V 正在运行中（可能正在使用该工作区）

**解决方法**：
1. 如有未提交文件：使用 P4V 提交（`p4 submit`）或撤销（`p4 revert`）
2. 如 P4V 运行中：关闭 P4V
3. 处理完成后重新点击"切换并打开 P4V"
